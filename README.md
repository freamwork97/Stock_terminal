# stock-terminal

관심 종목(한국/미국)을 실시간으로 모니터링하는 터미널 프로그램. [토스증권 Open API](https://developers.tossinvest.com/docs)를 데이터 소스로 사용한다.

## 사전 준비: 토스증권 Open API 발급

1. 토스증권 계좌가 없다면 먼저 개설한다.
2. 토스증권 WTS에 로그인 → **설정 > Open API** 메뉴로 이동해 `client_id` / `client_secret`을 발급받는다.
3. 같은 화면 하단 **허용 IP 관리**에서 이 프로그램을 실행할 PC(또는 서버)의 공인 IP를 등록한다.
   - 등록하지 않으면 모든 API 호출이 `403 Forbidden`으로 거부된다.
4. 참고: 이 API는 아직 WebSocket을 지원하지 않는다 (문서상 "추후 지원 예정"). 이 앱은 REST 폴링 방식으로 실시간성을 구현한다.

## 설치

```bash
uv sync
```

## 설정

프로젝트 루트에 `.env` 파일을 만든다 (`.env.example` 참고):

```
TOSS_CLIENT_ID=발급받은_client_id
TOSS_CLIENT_SECRET=발급받은_client_secret

# 선택: 폴링 주기(초), 차트 갱신 주기(초)
POLL_INTERVAL_SECONDS=3
CHART_REFRESH_SECONDS=30
```

## 실행

```bash
uv run stock-terminal
# 또는
uv run python -m stock_terminal
```

`.env`가 없거나 값이 비어있으면 앱은 실행되지 않고 설정 방법을 안내하는 메시지를 출력한다.

## 키 조작

단축키 목록은 평소 화면에 표시하지 않습니다. `F1` 또는 `?`로 명령 찾기를 열고 기능명·단축키를 검색할 수 있습니다. 검색 후 Enter로 결과에 이동하고, 다시 Enter로 선택 명령을 실행합니다. Esc 또는 F1로 닫습니다. 기존 단축키는 그대로 사용할 수 있습니다.


| 키 | 동작 |
|----|------|
| `a`, `/` | 통합 검색창 열기: 관심목록 검색 또는 새 종목 조회·추가 |
| `d` | 선택한 종목을 관심목록에서 삭제 |
| `u` | 마지막으로 삭제한 종목 복원 (이번 실행) |
| `t` | 선택한 종목의 알림 상한가/하한가 설정 |
| `h` | 이번 실행의 최근 가격 알림 이력 (최대 100건) |
| `b` | 전체 가격 알림 소리 켜기·끄기 (화면 알림·이력 유지) |
| `p` | 선택 종목의 가격 알림 중지·재개 (가격 조건 유지) |
| `m` | 차트 모드 전환 (캔들 ↔ 라인) |
| `i` | 차트 봉 주기 전환 (일봉 ↔ 1분봉) |
| `v` | 화면 전환 (전체 보기 → 차트만 보기 → 목록만 보기) |

| `Esc` | 검색 해제 / 대화상자 취소 |
| `Ctrl+Enter` | 검색창의 코드를 직접 조회 (기존 종목이 일부 검색될 때도 가능) |
| `s` | 등록순 → 심볼순 → 등락률 내림차순 정렬 |
| `r` | 현재가·차트 즉시 새로고침 |
| `q` | 종료 |

종목 코드는 국내는 6자리 숫자(예: `005930`), 미국은 티커(예: `AAPL`)를 그대로 입력한다. 별도 검색 API가 없어 정확한 코드를 알아야 하며, `a`로 추가할 때 `/api/v1/stocks` 조회 결과(종목명/시장)를 보여줘 오탈자를 확인할 수 있다.

지수는 `KOSPI`, `KOSDAQ`(또는 `코스피`, `코스닥`)를 입력하면 `/api/v1/market-indicators/*` 엔드포인트로 조회된다. 토스증권 Open API가 지수로 제공하는 것은 이 두 개뿐이며(그 외 미국채/국채 지표 제외), S&P500·나스닥 등 해외 지수는 지원하지 않는다. 지수는 통화가 아니라 포인트(pt) 단위로 표시된다.

## 화면 사용

터미널 너비가 150칸 미만이면 목록과 차트를 위아래로, 그 이상이면 좌우로 배치합니다. `v`로 목록이나 차트만 크게 볼 수 있으며, 목록의 나머지 상세 열은 가로 스크롤로 확인할 수 있습니다. 가격 알림 열에는 설정된 상한·하한을 표시합니다.

`a`와 `/`는 같은 검색창을 엽니다. 등록된 종목은 심볼·종목명으로 찾고 Enter로 목록에 이동합니다. 관심목록에 없는 종목은 정확한 코드 입력 후 Enter 또는 `종목 조회` 버튼으로 조회하고, 종목명을 확인한 뒤 다시 Enter를 누르거나 `관심목록에 추가` 버튼을 누릅니다. 조회 성공 시 추가 버튼으로 포커스가 이동하며, Esc로 취소할 수 있습니다. 추가하면 검색을 해제하고 해당 종목을 선택합니다. 일부 관심종목이 검색되는 경우에도 `종목 조회` 버튼으로 새 코드를 조회할 수 있습니다.

검색은 표시할 행만 좁히며 숨겨진 종목도 계속 시세를 갱신하고 알림을 판단합니다. 검색을 해제하면 기존 가격과 수신 시각을 유지합니다. 정렬할 때 선택한 종목을 유지하며, 등락률이 없는 종목은 등락률 정렬의 마지막에 표시합니다. 빈 관심목록과 검색 결과 없음은 화면에 다음 조작을 안내합니다.

차트는 조회 중·실패 상태를 표시하고, 주식 조회 오류와 차트 오류를 각 영역에 따로 표시합니다. 종목 추가 시 이미 등록된 종목의 설정은 보존하며, 조회 후 입력을 바꾸면 다시 조회해야 추가할 수 있습니다. 기준가 조회는 추가 이후 백그라운드에서 수행합니다. `u`는 가장 최근에 삭제한 종목 한 건을 알림 설정과 함께 목록 끝에 복원합니다.

정렬 방식·화면 모드·차트 모드·봉 주기는 `~/.stock_terminal/preferences.json`에 저장하여 재실행 시 복원합니다. 검색어와 검색창 표시 상태는 저장하지 않습니다. 선택 종목이 같은 상태에서 행 순서만 바뀌면 차트를 재조회하지 않고, 같은 종목의 차트를 갱신하거나 조회에 실패해도 기존 차트를 유지하며 갱신 상태를 별도로 표시합니다.

## 연결 장애 처리

연결 실패·응답 시간 초과·잘못된 API 응답이 발생하면 오류를 표시하고, 시세와 차트는 설정된 다음 갱신 주기에 다시 조회합니다. 장애 중에는 마지막으로 받은 데이터가 유지됩니다. HTTP 429는 한 번 재시도하며 대기 시간은 최대 60초로 제한합니다.

## 시세 상태 표시

관심목록의 상태 열은 `대기`, `정상`, `응답 누락`, `조회 실패`, `수신 지연`을 표시합니다. 조회가 실패하거나 응답에서 종목이 빠지면 기존 가격과 마지막 수신 시각을 유지하고 상태를 바꿉니다. 주식과 지수 조회는 별도로 처리하며, 정상 응답이 오면 상태가 자동 복구됩니다.

체결 시각과 마지막 수신 시각은 날짜를 포함한 PC 로컬 시간으로 각각 표시합니다. 마지막 수신 후 `30초 또는 폴링 주기의 3배 중 큰 값`을 넘으면 `수신 지연`이 됩니다. 같은 기준보다 오래된 체결은 `체결 오래됨`으로 표시하지만, 장 마감·휴장·거래 부진일 수도 있으므로 통신 장애를 의미하지 않습니다. 체결 시각이 없거나 시간대가 없으면 `체결시각 불명`, 미래로 5초 넘게 벗어나면 `체결시각 이상`을 표시합니다.

## 등락률 기준 가격

`기준 종가` 열에 실제 기준 거래일, 가격 출처(`분봉 추정` 또는 `일봉 대체`), 확정 여부를 표시합니다. 날짜가 다른 분봉, 미래 날짜의 일봉, 거래량이 없는 분봉, 유효하지 않은 가격은 종가 후보에서 제외합니다. 분봉 추정은 마감 부근의 최대 거래량 봉을 이용한 휴리스틱이므로 공식 종가와 다를 수 있으며, 현재 캔들 기반 기준가는 모두 `미확정`으로 표시합니다.

현재가와 기준가는 별도 작업으로 갱신합니다. 기준가 조회는 최대 3개 종목을 동시에 처리하므로 느린 기준가 응답이 현재가 폴링을 막지 않습니다. 일봉 대체값은 조회 완료 후 60초 뒤부터 재조회하며, 조회 실패·빈 응답·통화 정보 조회 실패는 종목별로 60 → 120 → 240 → 480 → 최대 900초로 재시도 간격을 늘립니다. 정상 응답 또는 시장별 기준일 변경 시 실패 횟수를 초기화합니다. 재조회 자격은 1초 간격으로 확인하되, 실제 시작은 진행 중인 기준가 작업과 동시 조회 제한에 따라 늦어질 수 있습니다. 데이터가 없으면 기존 기준가를 덮어쓰거나 갱신 완료로 기록하지 않습니다. 시장별 기준일이 바뀌었거나 출처를 알 수 없는 예전 저장 데이터는 재조회하며, 그동안 등락·등락률은 `-`로 표시합니다. 이전 형식의 관심목록도 그대로 불러올 수 있습니다. 조회 중 삭제·재추가한 종목에는 이전 요청의 결과를 적용하지 않으며, 종료 시 진행 중인 조회를 취소한 뒤 연결을 닫습니다.

## 가격 알림 동작

설정한 상한 이상 또는 하한 이하로 진입하면 벨·종목 강조·화면 알림이 한 번 발생합니다. 처음 조회한 가격이 이미 조건을 만족한 경우에도 한 번 알립니다. 같은 영역에 머무는 동안에는 쿨다운이 지나도 반복하지 않으며, 조건 밖으로 나온 뒤 다시 진입해야 재알림합니다. 반대편 조건으로 바로 이동한 경우는 새 진입으로 취급합니다.

같은 종목·같은 방향에는 60초 쿨다운을 적용합니다. 이 시간 안의 재진입은 건너뛰고, 대기 알림으로 남기지 않습니다. 이후 조건 밖으로 나왔다가 다시 진입하면 알립니다. 조회 실패나 응답 누락은 진입 상태를 초기화하지 않습니다. 알림 가격을 변경하거나 해제 후 다시 설정하면 새 조건으로 판단하며, 동일한 설정을 저장하면 기존 상태를 유지합니다.

`h`로 최근 100건의 알림 시각·방향·당시 가격·기준가를 확인할 수 있습니다. 이력 화면은 열 때의 목록이며 다시 열면 최신 내역이 보입니다. 이력·진입 상태·쿨다운은 이번 실행 동안만 유지되고, 알림 가격 설정은 저장됩니다. 재시작하거나 종목을 삭제 후 추가하면 첫 조회부터 다시 판단합니다.

`b`로 전체 가격 알림 소리를 끌 수 있습니다. 음소거 중에도 화면 알림·종목 강조·이력은 유지되며, 소리를 다시 켜도 지난 알림을 재생하지 않습니다. 상단 시세 상태에 `알림 소리 켜짐/꺼짐`을 표시하고 이 설정은 재실행 후에도 유지합니다.

`p`로 선택 종목의 가격 알림을 중지·재개합니다. 중지 중에는 해당 종목의 소리·화면 알림·이력을 발생시키지 않지만, 시세 갱신과 기존 상한·하한 조건은 유지합니다. 목록의 가격 알림 열에 `중지`를 표시하며, 중지 여부도 저장됩니다. 재개 후 다음 시세가 조건을 만족하면 한 번 알리고 이후에는 기존 재진입·쿨다운 규칙을 적용합니다. 알림 가격을 편집해도 중지 여부는 유지됩니다.

## 관심목록 저장 위치

`~/.stock_terminal/watchlist.json` 에 종목/알림 설정이 저장되어 재실행 시 그대로 불러온다.

저장은 같은 폴더의 임시 파일에 기록하고 flush/fsync를 마친 뒤 파일을 교체합니다. `watchlist.json.bak`에는 직전 정상 파일을 보관하며, 첫 저장에서는 최초 데이터도 백업합니다. 저장 실패 시 화면에 오류를 알리고 메모리 변경도 되돌립니다.

실행 시 원본이 없거나 JSON·저장값이 손상되어 있으면 유효한 백업을 자동 복원하고 안내합니다. 손상 원본은 `watchlist.json.corrupt-<고유값>`으로 별도 보존합니다. 백업 시점 이후 변경사항은 복구 결과에 포함되지 않을 수 있습니다. 원본과 백업 모두 복구할 수 없으면 두 파일을 유지한 채 경로를 안내하고 종료하므로, 파일을 확인·수정한 뒤 다시 실행하세요. 실행 도중 외부에서 원본이 손상된 경우에도 정상 백업을 덮어쓰지 않고 저장 오류를 표시합니다.

## 테스트

실제 API 자격증명 없이도 `respx`로 HTTP를 모킹해 인증/재시도/레이트리밋 로직을 검증할 수 있다:

```bash
uv run pytest
```


### 반복 실행·장애 검증

테스트에는 1,000회 시세 갱신 중 연결 실패·응답 누락·검색 전환·알림 반복을 섞는 가속 검증, 삭제·재추가 도중 늦게 도착한 시세 무시, 국내·미국 마감 시각 전환(미국 서머타임 전후), 하루 경과 후 기준가 재조회와 토큰 갱신을 포함합니다. 이는 모의 환경 검증이며 실제 절전·인터넷 단절·장 운영을 포함한 하루 이상 실환경 실행을 대체하지 않습니다.


## 진단 로그

실행하면 `~/.stock_terminal/logs/stock-terminal.log`에 UTC 시각 기준 JSON 로그를 기록합니다. 시작·종료·비정상 종료, 시세/차트/검색 조회 실패와 복구, 응답 누락, 기준가 재시도·갱신, 관심목록 복구와 저장 오류를 확인할 수 있습니다. 같은 작업의 동일한 조회 장애는 첫 발생과 이후 최대 분당 한 번 기록하며, 정상 데이터 수신 시 복구를 기록합니다.

한 파일은 약 2 MiB까지 기록하고 과거 파일 4개(`.1`~`.4`)를 유지합니다. 기록 항목은 작업 종류·오류 분류·HTTP 상태·개수·재시도 간격으로 제한합니다. 인증정보, 토큰, 요청 헤더/URL, API 응답 원문, 종목 입력값, 예외 문구와 전체 traceback은 기록하지 않습니다. 화면 설정이나 관심목록 파일 내용도 로그에 포함하지 않습니다.

로그 폴더를 만들 수 없으면 안내 후 로그 없이 실행하며, 실행 중 로그 쓰기가 실패해도 모니터링은 계속합니다. 실제 사용 중 문제가 발생하면 발생 시각(KST는 로그 UTC보다 9시간 빠름)과 당시 동작을 함께 알려주면 해당 구간의 로그를 기준으로 진단할 수 있습니다. 로그에는 실제 실행 시에만 기록이 쌓이며, 하루 이상 실환경 실행 검증은 별도로 필요합니다.


### 주기적 상태 확인

조회 실패가 없어도 60초마다 `poll_status` 로그를 기록합니다. 마지막 시세 수신 시각(UTC), 이번 조회 또는 직전 완료 조회의 소요 시간, 조회 진행 여부와 이번 실행의 누적 폴링·성공·실패·응답 누락·취소 건수를 포함합니다. 성공·실패·누락 건수는 정기·수동 폴링의 종목별 조회 결과를 세며, 새 종목 추가 직후의 단일 조회는 이 집계에 포함하지 않습니다. 마지막 수신 시각은 체결 시각이 아닌 이 폴링에서 실제 시세를 받은 시각입니다.

상단 시세 상태는 1초마다 갱신됩니다. 조회 소요 시간이 설정 주기를 넘으면 `폴링 지연`, 마지막 폴링 완료 후 `30초 또는 설정 주기의 3배 중 큰 값`을 넘으면 `갱신 중단 의심`으로 표시합니다. 최근 조회의 실패·누락은 정상으로 표시하지 않습니다. 관심목록이 비어 있으면 `대기`를 표시하면서 상태 로그는 계속 기록합니다. 조회 대기 중에도 상태 타이머는 동작하지만, 프로세스나 이벤트 루프 자체가 멈춘 경우에는 상태 로그도 끊기므로 마지막 로그 시각을 함께 확인해야 합니다.
