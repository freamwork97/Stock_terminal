# stock-terminal

한국·미국 관심 종목과 코스피·코스닥을 모니터링하는 TUI 프로그램입니다. [토스증권 Open API](https://developers.tossinvest.com/docs)를 REST 폴링 방식으로 조회합니다.

기본 화면은 관심목록과 차트에 집중합니다. 검색창·단축키 목록·전체 모니터링 상태는 필요할 때 열어 사용합니다.

## 빠른 시작

Python 3.11 이상과 `uv`, 토스증권 Open API의 `client_id` / `client_secret`이 필요합니다. API 설정에서 실행 PC 또는 서버의 공인 IP도 허용 목록에 등록하세요.

1. 프로젝트 폴더에서 의존성을 설치합니다.

   ```sh
   uv sync
   ```

2. [.env.example](.env.example)을 복사해 프로젝트 루트에 `.env`를 만들고 발급받은 값을 입력합니다.

   ```dotenv
   TOSS_CLIENT_ID=발급받은_client_id
   TOSS_CLIENT_SECRET=발급받은_client_secret

   # 선택 설정: 기본값은 현재가 3초, 차트 30초
   POLL_INTERVAL_SECONDS=3
   CHART_REFRESH_SECONDS=30
   ```

3. 실행합니다.

   ```sh
   uv run stock-terminal
   ```

   `uv run python -m stock_terminal`로도 실행할 수 있습니다. 인증정보가 설정되지 않으면 설정 안내 후 종료합니다.

## 기본 사용 흐름

### 명령 찾기

`F1` 또는 `?`를 눌러 기능명이나 단축키를 검색합니다. Enter로 검색 결과에 이동하고, 다시 Enter로 선택한 명령을 실행합니다. Esc 또는 F1로 닫습니다. 입력창에서 문자를 입력하는 중에는 F1을 사용하세요.

단축키 안내는 기본 화면에 표시하지 않지만, 아래 키는 그대로 사용할 수 있습니다.

| 키 | 기능 |
| --- | --- |
| `F1`, `?` | 명령 찾기 |
| `a`, `/` | 종목 검색·추가 |
| `Ctrl+Enter` | 검색창의 코드를 직접 조회 |
| `Esc` | 검색 해제·검색창 숨김 또는 대화상자 닫기 |
| `d` / `u` | 선택 종목 삭제 / 마지막 삭제 취소 |
| `s` | 등록순 → 심볼순 → 등락률 내림차순 정렬 |
| `r` | 현재가·차트 새로고침 |
| `m` / `i` | 캔들·라인 전환 / 일봉·1분봉 전환 |
| `v` | 전체 → 차트만 → 목록만 보기 |
| `t` | 선택 종목의 가격 알림 조건 설정 |
| `p` | 선택 종목의 알림 중지·재개 |
| `b` | 전체 가격 알림 소리 켜기·끄기 |
| `h` | 이번 실행의 알림 이력 |
| `o` | 모니터링 상태 |
| `q` | 종료 |

### 종목 검색·추가

1. `a` 또는 `/`로 검색창을 엽니다.
2. 등록된 종목은 심볼·종목명으로 찾고 Enter로 목록에 이동합니다.
3. 없는 종목은 정확한 코드를 입력하고 Enter로 조회합니다.
4. 조회된 종목명을 확인한 뒤 다시 Enter를 누르거나 **관심목록에 추가** 버튼을 누릅니다.

검색 결과가 일부 있어도 Ctrl+Enter 또는 **종목 조회** 버튼으로 새 코드를 조회할 수 있습니다. 입력을 바꾸면 이전 조회 결과는 무효화됩니다. 추가가 끝나면 검색창을 숨기고 새 종목을 선택합니다.

| 구분 | 입력 예시 |
| --- | --- |
| 국내주식 | `005930` |
| 미국주식 | `AAPL` |
| 국내지수 | `KOSPI`, `KOSDAQ`, `코스피`, `코스닥` |

새 종목 조회에는 정확한 코드가 필요합니다. 이 앱의 지수 지원 범위는 코스피·코스닥이며 지수 가격은 `pt`로 표시합니다.

검색으로 숨긴 종목도 시세 갱신과 알림 판단을 계속합니다. 이미 등록된 종목을 추가해도 기존 설정을 덮어쓰지 않습니다. 삭제 취소는 이번 실행에서 가장 최근에 삭제한 한 종목을 알림 설정과 함께 목록 끝에 복원합니다.

### 화면과 상태 확인

터미널 너비가 150칸 미만이면 목록·차트를 위아래로, 그 이상이면 좌우로 배치합니다. 상세 열은 가로 스크롤로 확인할 수 있습니다. 새로고침·재정렬 중에도 목록의 스크롤 위치와 선택한 종목을 유지합니다.

선택 종목이 같고 행 순서만 바뀌면 차트를 재조회하지 않습니다. 같은 종목의 차트 갱신이나 조회 실패 중에는 기존 차트를 유지하고, 종목·봉 주기가 바뀌면 새 데이터를 조회합니다.

관심종목 수·전체 시세 상태·조회 주기·마지막 수신·알림 소리 상태는 **명령 찾기 → 모니터링 상태** 또는 `o`로 확인합니다. 상태 창은 열린 동안 1초마다 갱신됩니다.

## 가격 알림

`t`로 상한·하한 가격을 설정합니다. 빈 값은 해당 조건을 해제하며, 가격은 유한한 양수여야 합니다.

- 상한 이상 또는 하한 이하로 진입하면 소리·종목 강조·화면 알림이 한 번 발생합니다. 첫 조회부터 조건을 만족해도 한 번 알립니다.
- 같은 영역에 머무르면 반복하지 않습니다. 조건 밖으로 나온 뒤 재진입해야 다시 알리며, 반대편 조건으로 바로 이동하면 새 진입으로 판단합니다.
- 같은 종목·같은 방향에는 60초 쿨다운이 있습니다. 이때 건너뛴 알림은 나중에 재생하지 않습니다.
- 조회 실패·응답 누락은 진입 상태를 초기화하지 않습니다. 조건 변경은 새 조건으로 판단하고, 동일한 조건을 저장하면 기존 상태를 유지합니다.

| 제어 | 동작 |
| --- | --- |
| 전체 음소거 (`b`) | 소리만 끄고 화면 알림·강조·이력은 유지합니다. 해제 시 지난 알림을 재생하지 않습니다. |
| 종목별 중지 (`p`) | 해당 종목의 알림·이력을 중지합니다. 가격 조건과 시세 갱신은 유지하며 목록에 `중지`를 표시합니다. |
| 알림 이력 (`h`) | 이번 실행의 최근 100건을 최신순으로 표시합니다. 다시 열면 최신 내역을 확인할 수 있습니다. |

음소거와 종목별 중지 여부는 저장합니다. 종목 알림을 재개하면 다음 시세부터 새로 판단합니다. 이력·진입 상태·쿨다운은 이번 실행 동안만 유지합니다.

## 데이터 상태와 기준 가격

### 수신 상태

목록에서는 `대기`, `정상`, `조회 실패`, `응답 누락`, `수신 지연`을 구분합니다. 체결 시각과 수신 시각은 날짜를 포함한 PC 로컬 시간으로 표시합니다.

마지막 수신 후 **30초 또는 폴링 주기의 3배 중 큰 값**을 넘으면 수신 지연입니다. 체결이 오래됐거나 시각이 불명확한 경우도 별도로 표시합니다. 장 마감·휴장·거래 부진으로 체결이 오래된 경우와 통신 장애를 구분하기 위한 표시입니다.

모니터링 상태 창에서는 조회가 설정 주기보다 오래 걸리면 **폴링 지연**, 마지막 폴링 완료 후 위 지연 기준을 넘으면 **갱신 중단 의심**을 표시합니다. 조회 주기는 요청 완료 후 다음 요청까지 기다리는 간격이므로 실제 갱신 간격에는 조회 시간도 포함됩니다.

### 등락률 기준가

`기준 종가` 열에 기준 거래일·출처·확정 여부를 표시합니다. 현재 기준가는 **마감 부근 분봉의 최대 거래량 가격으로 추정**하거나 **일봉으로 대체**한 값입니다. 공식 종가와 다를 수 있어 모두 `미확정`으로 표시합니다.

날짜가 다른 분봉, 미래 날짜의 일봉, 거래량이 없는 분봉, 유효하지 않은 가격은 후보에서 제외합니다. 기준일이 바뀌었거나 출처를 알 수 없는 저장 데이터는 재조회하며, 사용할 수 있는 기준가가 없으면 등락·등락률을 `-`로 표시합니다.

현재가와 기준가는 별도 작업으로 갱신하고, 기준가 조회는 최대 3개 종목을 동시에 처리합니다. 일봉 대체값은 조회 완료 후 60초 뒤부터 다시 조회합니다. 실패·빈 응답·통화 정보 조회 실패 시에는 종목별로 60 → 120 → 240 → 480 → 최대 900초로 간격을 늘립니다. 정상 응답이나 시장별 기준일 변경 시 실패 횟수를 초기화합니다.

연결 실패·타임아웃·잘못된 응답 후에도 다음 폴링에서 재시도하고 마지막 데이터를 유지합니다. HTTP 429는 최대 60초 기다린 뒤 한 번 재시도합니다. 조회 중 삭제·재추가한 종목에는 이전 요청의 결과를 적용하지 않습니다.

## 저장과 복구

데이터는 사용자 홈의 `.stock_terminal` 폴더에 저장합니다. Windows에서는 일반적으로 `%USERPROFILE%\.stock_terminal`입니다.

| 파일 | 내용 |
| --- | --- |
| `watchlist.json` | 종목·알림 조건·중지 여부·기준가 |
| `watchlist.json.bak` | 직전 정상 관심목록 백업 |
| `watchlist.json.corrupt-<고유값>` | 복구 과정에서 보존한 손상 원본 |
| `preferences.json` | 정렬·화면·차트 모드·봉 주기·음소거 설정 |
| `logs/stock-terminal.log` | 진단 로그 |

관심목록은 같은 폴더의 임시 파일에 기록·동기화한 뒤 교체합니다. 저장 실패 시 기존 파일을 유지하고 메모리 변경도 되돌립니다. 첫 저장에서는 최초 데이터도 백업합니다.

시작 시 원본이 없거나 손상됐으면 유효한 백업을 복원하고 안내합니다. 백업 이후 변경사항은 복구되지 않을 수 있습니다. 둘 다 복구할 수 없으면 파일을 보존하고 경로를 안내한 뒤 종료합니다. 파일을 확인·수정하고 다시 실행하세요.

화면 설정은 재실행 시 복원하지만 검색어·검색창 표시 상태는 저장하지 않습니다. 잘못된 화면 설정은 안내 후 기본값으로 대체합니다.

## 진단 로그

로그는 UTC 시각 기준 JSON Lines 형식입니다. 한국 시각은 UTC에 9시간을 더하면 됩니다.

- 시작·종료·비정상 종료, 조회 실패·복구·응답 누락, 기준가 재시도, 저장 오류·복구를 기록합니다.
- 동일한 조회 장애의 반복 기록은 최대 분당 한 번으로 제한합니다.
- 장애가 없어도 60초마다 `poll_status`를 기록합니다. 마지막 수신 시각, 조회 소요 시간·진행 여부, 누적 폴링·성공·실패·누락·취소 건수를 포함합니다.
- 성공·실패·누락은 정기·수동 폴링의 종목별 결과 건수입니다. 추가 직후 단일 종목 조회는 이 집계에 포함하지 않습니다.
- 파일당 약 2 MiB, 과거 파일 4개(`.1`~`.4`)를 순환 보관합니다.

인증정보·토큰·요청 헤더/URL·응답 원문·종목 입력값·예외 문구·전체 traceback·저장 파일 내용은 로그에 넣지 않습니다. 로그를 만들 수 없으면 안내 후 실행하며, 쓰기 실패도 모니터링을 중단시키지 않습니다.

문제가 생기면 발생 시각과 당시 동작을 로그와 함께 확인하세요. 조회 응답 대기 중에도 상태 로그를 기록하지만, 프로세스나 이벤트 루프 자체가 멈추면 로그도 끊기므로 마지막 기록 시각을 함께 확인해야 합니다.

## 개발과 검증

```sh
uv run pytest
```

실제 API 자격증명 없이 HTTP 모의 응답과 헤드리스 TUI 테스트를 실행합니다. 인증·재시도·로그 개인정보 보호·저장 복구·키보드 조작·화면 배치·스크롤 유지·알림 제어 등을 검증합니다.

1,000회 반복 갱신 중 장애·응답 누락·검색 전환·알림을 섞는 가속 검증과 국내·미국 마감 전환, 서머타임 전후, 하루 경과 후 기준가·토큰 갱신도 포함합니다. 이는 실제 절전·네트워크 재연결·장 운영을 포함한 하루 이상 실환경 실행을 대체하지 않습니다.
